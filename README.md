# Ripple Server Project

## Description

This repository contains all the files related to the server-end daemons for the Ripple Glasses project. This server will be used for testing and experimentation.
As of now, there are two primary functions within the server: realtime uploads and training uploads. The realtime uploads are for presentation purposes and should simulate what the actual glasses will do.
The training uploads help refine and train the model. The endpoint code is found within `audio-uploader/main.py`.
The raw audio files are found in `audio-uploader/realtime-uploads/` or `audio-uploader/training-uploads/`,
the audio environment files are in `environment-uploader/realtime-uploads/` or `environment-uploader/trainig-uploads/`. 
The model is found in `environment-classifier/` and mostly maintained by Spencer Goff.  

## Development flow

Two main environments; production/master and development. Production/master contains the tested and reviewed codebase. It should be used for presentations
and should only be modified after the approval of Spencer and Sam.
The pipeline works as follows: the microcontroller determines an environment, production or development (it defaults to production) -> the microcontroller sends an audio file to a particular endpoint (the endpoints are defined in `ripple_site/config`) -> Depending on what endpoint the audio clip was sent to, nginx will forward that information to a specific port. That file is then handled by one of two service-daemons - `audio-uploader-prod.service` or `audio-uploader-dev.service` (these are defined in `ripple_server/deploy` and symlinked to `/etc/systemd/system/`) -> The audio-uploader service handles whether they are deposited in the `training-uploads/` or `realtime-uploads/` folder. For production environments, these files are in `/srv/projects/ripple_server/audio-uploader/`. For development environments, these files are uploaded to whatever cloned repo is being used. Before the dev environment works, it's necessary to run the following command `sudo dev-claim`, which will change the `*dev.service` ExecStart, Environment variables, and WorkingDirectory, allowing a specific user to test new functionality without disrupting production code. When the user is done, they can run `sudo dev-release` so other developers can test their code. Run `sudo dev-status` to see who owns the dev environment. These scripts were generated by AI and symlinked into `usr/local/bin`. I will write more notes on how to properly clone the github repo and set up the environment on your home directory. -> A separate service `environment-realtime-watcher-prod.service` or `environment-realtime-watcher-dev.service` will observe the files in `/srv/projects/ripple_server/audio-uploader` and when a new one is added, it will analyze it and produce a batch of environment analyses, which will be put in `environment-uploader/training-uploads` or `environment-uploader/realtime-uploads`. -> If it is realtime, the audio-uploader and html file will pull the data from `lastest.json` and post it to the website. This is the entire pipeline.

## Development environment setup

1. Clone/fetch the github repo in your home directory
2. Run the following commands within `~/ripple_server/audio-uploader` and `~/ripple_server/environment-classifier`:
```
sudo apt update
sudo apt install python3-venv
```
3. Create virtual environment using `python3 -m venv ~/ripple_server/audio-uploader/venv` and `python -m venv ~/ripple_server/environment-classifier/.venv`
4. Activate venv: `source ./venv/bin/activate` 
5. Install dependencies:
```
pip install -r requirements.txt
```
6. Run the following commands to create folders for uploading audio and environment classifiers
```
mkdir ~/ripple_server/audio-uploader/realtime-uploads
mkdir ~/ripple_server/audio-uploader/training-uploads
mkdir ~/ripple_server/environment-uploader
mkdir ~/ripple_server/environment-uploader/realtime-uploads
mkdir ~/ripple_server/environment-uploader/training-uploads
sudo chgrp -R devteam ~/ripple_server
sudo chmod -R g+rwX ~/ripple_server
sudo apt install acl
sudo setfacl -m u:www-data:x ~/
```
You can test everything using this command: `curl -i -X PUT http://127.0.0.1:8080/realtime/1.wav -H "x-api-key: <API_KEY>" \ --data-binary @/srv/projects/ripple_server/audio-uploader/training-uploads/<some-existing-file>.wav` AND `curl -i -X PUT https://summit-innovative.duckdns.org/dev/realtime/1.wav \ -H "x-api-key: <API_KEY>" \ --data-binary @/srv/projects/ripple_server/audio-uploader/training-uploads/<some-existing-file>.wav`
